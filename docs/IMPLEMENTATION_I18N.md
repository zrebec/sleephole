## 1. Owner requirements (2026-09-30, verbatim intent)

1. **Default language = English (EN).** Slovak (SK) is the second language.
2. **Simple switch in Settings.** When the user switches to SK, the choice is **stored in SQLite** (SwiftData)
   and stays forever – no restart, no online account, nothing else.
3. **Everything** visible must have both variants: labels, buttons, section titles, picker options
   (e.g. "Hnedý šum" → "Brown noise"), footers, alerts, confirmation dialogs, notifications, guide texts,
   result screens, statistics, credits, accessibility labels, building names, **and the signs painted on
   buildings** (MÚZEUM → MUSEUM …).
4. **Privacy:** the user owns their data. No account, no server, no analytics now. (Maybe one day an
   *anonymous, opt-in* usage summary to know what to improve – **not planned**, do not build.)
5. EN is important for **Kenney** (credits/email) and for **Apple** (App Store review later).

**Key technical fact:** SwiftUI `Text("literal")` resolves strings with `Bundle.main` and the **system**
language. It does **not** follow an in-app language choice. Because the owner wants an in-app switch stored in
SQLite (not iOS Settings → per-app language), every UI string must be resolved through **our own** helper that
uses the bundle of the chosen language.

## 4. Architecture (recommended)

### 4.1 One source of truth: String Catalog, English keys
- Add `SleepHole/Resources/Localizable.xcstrings` (Xcode String Catalog). **Source language `en`**, translation
  `sk`. **Keys = the English text** (natural for Xcode, readable in code), with a `comment` for context where the
  meaning is ambiguous (e.g. "Build" verb vs noun).
- `project.yml`: `developmentLanguage: en`; Info.plist `CFBundleDevelopmentRegion: en`,
  `CFBundleLocalizations: [en, sk]`. Run `xcodegen generate`.
- **Plurals** via catalog plural variations (EN: one/other, SK: one/few/many). Replace the hand-made `SK`
  helper (`GuideView.swift` top) completely.

### 4.2 In-app language (no restart)
```swift
enum AppLanguage: String, Codable, CaseIterable, Identifiable { case en, sk
    var id: String { rawValue }
    var nativeName: String { self == .en ? "English" : "Slovenčina" }   // never translated
    var locale: Locale { Locale(identifier: rawValue == "sk" ? "sk_SK" : "en_US") }
    var bundle: Bundle { Bundle(path: Bundle.main.path(forResource: rawValue, ofType: "lproj")!) ?? .main }
}

/// The ONLY way UI text is produced. `L("Bedtime at \(time)")` – LocalizationValue keeps interpolation + plurals.
@MainActor func L(_ key: String.LocalizationValue) -> String {
    String(localized: key, bundle: Lang.current.bundle, locale: Lang.current.locale)
}
@MainActor enum Lang { static var current: AppLanguage = .en }   // set by AppModel
```
- **Storage (SQLite):** add `var languageRaw: String?` to the SwiftData model `UserProgress`
  (`SleepHole/Persistence/UserProgress.swift`, one row). `AppModel` exposes
  `var language: AppLanguage { didSet { persist; Lang.current = language; bump uiVersion; reschedule reminders } }`.
- **Live switch:** root view gets `.environment(\.locale, language.locale)` (dates, numbers, pickers) and
  `.id(model.uiVersion)` so every view re-evaluates its `L(...)` calls immediately.
- **Views:** use `Text(L("…"))` (a `String` → `Text` shows it verbatim, no second lookup), `Button(L("…"))`,
  `Label(L("…"), systemImage:)`, `Toggle(L("…"), isOn:)`, `Picker(L("…"), …)`, `.navigationTitle(L("…"))`,
  `Section(L("…"))`, `.confirmationDialog(L("…"), …)`, `.alert(L("…"), …)`, `.accessibilityLabel(L("…"))`.
  **Never** leave a bare `Text("Slovak literal")`.
- **Enums with titles** (`AlarmSound.title/detail`, `Ambience.title/detail`, `AppSettings.timerTitle`, outcome
  labels) return `L(...)`. Their **persisted raw values stay language-free** (already true: `alarm_gentle`,
  `brown`, `rain`, …).
- **Settings UI:** Section "Language · Jazyk" at the TOP of Settings with a segmented picker
  `English | Slovenčina` (native names). Also on the first guide page (Q4).
- **No migration (Q1 = no):** when `languageRaw == nil` the app runs in **EN** – also on the owner's phone
  that already has Slovak data; he switches to SK himself in Settings (or on the first guide page).
- **Ready for more languages (Q11):** nothing may assume exactly two languages – `AppLanguage.allCases` drives the
  pickers, sprite variants use `files[lang]`-style lookup with a fallback to the default file, catalog names use
  `name(lang)` with fallback to EN. Adding CZ later = one enum case + catalog translations + optional sign sprites.
- **Backup:** add `language: String?` to `BackupFile` (optional → old backups still load).

### 4.3 Dates, times, numbers
- Replace fixed `DateFormatter("H:mm")` (`clockFormat` in `UI/TodayView.swift`, `NightDetail.time/timeSec`
  in `UI/StatsView.swift`, `ProbeLog.timeFormat` stays technical) with helpers
  `Fmt.time(_ date)`, `Fmt.timeSec(_ date)`, `Fmt.time(TimeOfDay)`, `Fmt.dayMonth(NightKey)`,
  `Fmt.fullDate(NightKey)` built on `Date.FormatStyle` with `Lang.current.locale` (Q3: 12/24 h from the system in EN).
- `TimeOfDay.description` (SleepCore, "%d:%02d") is used in UI strings (nap window, notifications) → route UI
  uses through `Fmt.time(TimeOfDay)`; keep `description` for logs/tests.
- Numbers: always pass numbers as interpolation arguments of `L(...)` (the catalog formats them); years via
  `Fmt.fullDate` (no "2 026").

### 4.4 Building names (catalog)
- `tools/render/make_recipes.py`: every `add(...)` gets `nameEN` next to `nameSK` (table §5.12).
- `SleepCore/Sources/SleepCore/Catalog.swift`: `CatalogEntry.nameEN: String?` (optional → old catalog decodes),
  `func name(_ lang: String) -> String`. Re-run the renderer so `catalog.json` gets `nameEN`
  (see `AGENTS.md` commands; **run outside the sandbox**).

### 4.5 Signs painted on buildings (sprites)
- 9 sprites carry Slovak text: `l2-museum-a` (MÚZEUM), `l2-museum-b` (GALÉRIA), `l2-library-a`, `l2-library-b`
  (KNIŽNICA), `l3-townhall` (RADNICA), `l3-school` (ŠKOLA), `l3-firestation` (HASIČI), `l3-police` (POLÍCIA),
  `l3-hospital` (NEMOCNICA).
- `make_recipes.py`: `sign()` takes `{"sk": "...", "en": "..."}`; the generator emits the normal recipe (SK)
  **plus** an EN variant written to `L3/l3-police.en.png` etc. Catalog entry gets optional `fileEN`.
  **Ids stay the same** (ids are persisted in users' databases – never rename).
- `SpriteLibrary.image(for:)` picks `fileEN` when the language is EN (cache key must include the language).
- Check the long EN signs fit ("FIRE STATION", "TOWN HALL" uses an explicit position/width in
  `make_recipes.py`); look at `docs/previews/contact_sheet.png` after rendering.

### 4.6 Notifications
- Texts are resolved when scheduled. On language switch: `Notifications.scheduleReminders(...)` again. Night
  notifications scheduled at "Začať stavbu" keep the language they were scheduled in (acceptable).

### 4.7 What stays untranslated
- Brand "SleepHole", "Kenney", composer names, "CC BY 4.0", URLs, emojis.
- Raw technical logs: `LifecycleMonitor` raw lines, `ProbeLog` export, `AudioKeeper` interruption names,
  `NightLog` event kind names in the developer journal (they are for agents).
- The user's wake code.
